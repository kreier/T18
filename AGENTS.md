# AGENTS.md — AI Agent Guidance & Architectural Reference

This document serves as the primary technical specification and operational playbook for autonomous AI coding agents working on the `flynn0/T18` repository.

---

## 1. System Overview & Architecture

`flynn0/T18` is an edge-native, zero-trust telemetry fleet monitoring system tailored for the **LILYGO TTGO T18** (and fully compatible with **LILYGO T8**, ESP32 DevKit V1, and custom boards):

- **Edge Nodes (Firmware)**: ESP32 microcontrollers operating unattended on 18650 battery or USB. Every 10 minutes, nodes wake from light sleep, run 13-channel promiscuous congestion surveys (with dynamic LED feedback and BOOT button interrupt), 2.4 GHz spectrum Wi-Fi scans, BLE sweeps with advertising payload de-randomization and 24-hour flash persistence, network latency probes, and IO35 battery sensing, uploading telemetry before returning to light sleep.
- **Edge Backend (Worker & D1)**: Cloudflare Worker written in TypeScript deployed at `https://t18.dhsp.workers.dev` backed by Cloudflare D1 (`t18-mon-db`). Handles device registration, bearer token validation, telemetry batch ingestion, two-tier caching, automated 30-day data retention, web serial flasher assets, and zero-redirect OTA streaming proxies.
- **Dual Dashboards & Web Installer**: Server-rendered dashboard on Cloudflare Worker (`https://t18.dhsp.workers.dev`) and static mirror on GitHub Pages (`https://flynn0.github.io/T18`) driven by a single-source frontend engine in `worker/src/frontend.ts`. Includes in-browser Web Serial firmware flashing via ESP Web Tools.

## 2. Hardware Profiles & ADC Battery Sensing

| Board Target | Status LED Pin | ADC Battery Pin | Divider Ratio | Notes |
| ------------ | -------------- | --------------- | ------------- | ----- |
| **BOARD_T18** (LILYGO T18) | GPIO 5 | GPIO 35 | 0.50f (100k/100k) | Standard LiPo 18650 single-cell |
| **BOARD_T8** (LILYGO T8) | GPIO 21 | GPIO 35 | 0.50f (100k/100k) | Standard LiPo single-cell |
| **BOARD_DEVKIT** (DevKit V1) | GPIO 2 | -1 (Disabled) | 0.50f | AC / USB powered |
| **BOARD_CUSTOM** | User-defined | User-defined | User-defined | Custom GPIOs |

### Battery Voltage Calculations
- ADC voltage is read using `analogReadMilliVolts(pin)` across 5 averaged samples and divided by `hw.battery_divider`.
- Standard single-cell LiPo curve spans 3.30 V (0%) to 4.20 V (100%).
- Formatted strings required by UI:
  - `"Running on battery for XXXh (DD days X hours)"`
  - `"Estimated runtime YYYh (DD days Y hours)"`

## 3. Key Invariants & Non-Negotiable Rules

1. **Dual Build Firmware Parity**: Embedded logic resides in `firmware/include/*.h`. `firmware/src/main.cpp` and `firmware/T18/T18.ino` are minimal wrappers.
2. **Flash Wear & Memory Safety**: In-memory first telemetry transmission; raw flash circular buffer (`raw_spool`) used only when offline.
3. **Zero-Redirect OTA Streaming**: Direct binary streaming proxy via `/api/ota/download/:filename` and `/firmware/*`.
4. **Single-Source Frontend**: Generated by `renderDashboardHtml()` in `worker/src/frontend.ts`. Run `npm run build:docs` after editing.

## 4. Backend & Cloudflare D1 Management

### Two-Tier Caching Architecture
1. **Level 1 (Isolate In-Memory Cache)**: Fast global map in Worker memory (`maxAge: 15s`).
2. **Level 2 (D1 Snapshot Cache)**: `station_overview_cache` table (`maxAge: 600s`).
* When telemetry is uploaded (`telemetry.ts`), **both caches are explicitly invalidated** for that station so fresh data is visible immediately.

### D1 Migration Process
New migrations are added to `worker/migrations/` using zero-padded prefixes:
```bash
# Apply migrations locally
cd worker && npx wrangler d1 migrations apply t18-mon-db --local

# Apply migrations remotely to production
cd worker && npx wrangler d1 migrations apply t18-mon-db --remote
```

### Scheduled Maintenance (Cron)
A cron trigger runs daily at `00:15 UTC` (`cron.ts`):
1. Aggregates the previous UTC day's raw measurements into `daily_summaries`.
2. Purges raw `measurements`, `station_discovered_aps`, `station_bluetooth_summary`, and `station_battery_history` older than 30 days.
3. Purges `station_overview_cache` older than 24 hours.

## 6. Standard Verification & Testing Commands

Before committing changes, agents **must** run the following verification steps:

```bash
# 1. Validate TypeScript compiler on Worker backend
cd worker
npm run build

# 2. Recompile frontend and validate embedded JavaScript syntax
npm run build:docs

# 3. Check git status to ensure docs/index.html & docs/404.html are generated
git status

# 4. Deploy worker to production Cloudflare Edge
npx wrangler deploy
```
